Правило входа

Когда заводить агрегат

Агрегат нужен тогда и только тогда, когда есть инвариант — правило, которое обязано выполняться при каждой записи. Нет инварианта — нет агрегата, пиши обычный CRUD. «У сущности много полей» — не инвариант. «Это важная таблица» — не инвариант.

Словарь

ПонятиеОпределениеПризнак, что это оно
Entity Объект с идентичностью, которая переживает изменение полей Два объекта с одинаковыми полями, но разными id — разные
Value Object Неизменяемый объект без id, сравнивается по значению Money(100, 'UAH') равен любому другому Money(100, 'UAH')
Aggregate Кластер объектов, меняющийся как одно целое ради инварианта Есть правило, которое нельзя проверить, глядя на один объект
Aggregate Root Единственная дверь внутрь агрегата Снаружи ничего внутри агрегата не достижимо, кроме как через root
Repository Коллекция агрегатов; сохраняет и достаёт целиком Один репозиторий на агрегат, а не на таблицу
Domain Event Факт, который уже случился внутри домена Имя в прошедшем времени: OrderPaid, не PayOrder
Application Service (use case) Оркестровка одного сценария: транзакция, репозитории, публикация событий Бизнес-правил внутри нет — они в агрегате

Три закона границы агрегата

  1. Агрегат должен быть маленьким. Его граница — это граница транзакции, а транзакция — это блокировка. Агрегат «Event со всеми местами» означает, что все покупатели концерта стоят в одной очереди.
  2. Ссылайся на другие агрегаты по id. Внутри Hold лежат seatId, а не объекты Seat. Иначе граница расплывается и в память тянется полстраницы базы.
  3. Одна транзакция — один агрегат. Правило по умолчанию. Отступать можно, но только через ADR с посчитанной ценой — как мы делаем в M1-14.

Два пояса, а не один

Агрегат даёт хороший UX: понятная ошибка, аккуратный 409, осмысленное сообщение. Constraint даёт гарантию: он сработает даже для кода, который написан мимо домена. Агрегат без constraint — надежда на дисциплину. Constraint без агрегата — правило, размазанное по сервисам.

Слои и направление зависимостей

api            → application → domain
infrastructure → application → domain
                               ↑
                        никуда не зависит

domain/ не импортирует NestJS, TypeORM, pg, Redis — ничего. Интерфейс репозитория (порт) объявлен в domain/, реализация живёт в infrastructure/. Проверяется линтером в M1-15, а не честным словом.
