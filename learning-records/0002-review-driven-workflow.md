# Формат работы: issue → самостоятельная реализация → ревью агента

Роман явно попросил (2026-09-10) режим: агент составляет план, Роман сам делает задачи (issues),
агент делает code review и либо принимает, либо возвращает на доработку.

## Implications

- **Агент не пишет продакшн-код проекта.** Писать можно: примеры внутри уроков, демонстрационные
  сниппеты, тестовые сценарии для иллюстрации — но не реализацию issue.
- Ревью — основной механизм обратной связи, а значит основной инструмент обучения. Оно должно
  быть tight: конкретные строки, конкретные последствия, максимум 3–5 blocking-замечаний за раз.
- Замечания формулировать как вопрос о последствии («что произойдёт, если два запроса придут
  одновременно?»), а не как готовую правку — иначе Роман учится копировать, а не думать.
- Каждый issue должен иметь проверяемый Definition of Done, иначе ревью превращается в спор.
