# M0-01 — Структура репозитория и тулинг

Status: done — сделано агентом 2026-09-11 по явной просьбе Романа, см. Comments

## Задача

Завести монорепо с двумя приложениями и общим тулингом:

```
apps/server   — NestJS
apps/web      — React + TypeScript (TanStack Start)
```

Настроить TypeScript в strict-режиме, линтер, Prettier, единые скрипты в корне.

> Имя папки — `apps/server`, не `apps/api` (решение Романа 2026-09-11).
> Линтер — **oxlint**, не ESLint (решение Романа 2026-09-11).

## Решение по конфигам (обсуждено 2026-09-10)

Отдельные tsconfig и конфиги линтера для `api` и `web` — **да**, иначе никак: у приложений
несовместимые настройки компилятора. Но отдельные конфиги делаются **через общую базу**, а не
двумя независимыми копиями.

Обязательно **общее** (иначе строгость разъедется через месяц):
`strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `forceConsistentCasingInFileNames`,
`isolatedModules`, `skipLibCheck` — в `tsconfig.base.json`, оба приложения его `extends`.

Обязательно **разное** (перечислить в конфиге явно, каждое — осознанно):

| | `apps/server` | `apps/web` |
| --- | --- | --- |
| `lib` | `ES2023` — **без DOM** | `ES2023`, `DOM`, `DOM.Iterable` |
| `jsx` | нет | `react-jsx` |
| декораторы | `experimentalDecorators`, `emitDecoratorMetadata` — нужны NestJS | нет |
| `types` | `node`, `jest` | окружение сборщика |
| `module` / `moduleResolution` | под Node | под сборщик |

Почему `DOM` не должен попасть в API: с ним `document`, `localStorage` и `window`
типизируются как существующие. Код скомпилируется и упадёт в рантайме.

## Definition of Done

- `npm run lint` и `npm run typecheck` проходят в обоих приложениях, запускаются из корня
- `apps/tsconfig.base.json` существует; настройки строгости заданы **в нём одном**, не продублированы
- В `apps/server` отсутствует `DOM` в `lib` — проверяется тем, что `document.title` не компилируется
- Линтер: общая база + правила, специфичные для приложения (react-хуки только для web)
- `.gitignore` покрывает `node_modules`, `dist`, `.env`
- В git нет ни одного `.env` с реальными значениями — только `.env.example`
- Импорт из `apps/web` в `apps/server` (и обратно) роняет `npm run lint`, включая запись через `../..`

## Граница между приложениями (решено 2026-09-10)

Инструмент — **oxlint**, правило `no-restricted-imports` с `patterns`. Контракт между вебом и
API проходит **через спеку OpenAPI**, а не через импорты исходников.

Направление источника истины — в одну сторону, без исключений:

```
DTO в NestJS  →  спека OpenAPI  →  типы для веба
   (M2-06)         (генерится)      (генерятся)
```

Спека не пишется руками. Типы веба не пишутся руками. Правит их только тот, кто правит DTO.

### Что учесть, когда будешь делать

**Правило линтера ловит не всё, что кажется.** Оно рассчитано на статические `import`.
Отдельно проверь `require()` и динамический `import()` — напиши по одному примеру каждого и
убедись, что линтер краснеет. Если не краснеет, дыра в границе есть.

**Относительные пути — главная лазейка.** Запрет по алиасу `@api/*` не мешает написать
`../../api/src/...`. Шаблон должен ловить путь до приложения, а не только алиас.

**Правило, которое не проверили, не работает.** Заведи файл с заведомо запрещённым импортом,
убедись, что `npm run lint` падает, и только потом убирай. Ровно та же логика, что и с тестом,
который обязан краснеть при удалении кода.

**Сгенерированные типы лучше коммитить.** Тогда изменение контракта видно в diff при ревью —
это самый дешёвый способ заметить breaking change. И сборка веба не требует поднятого API.

**Дрейф контракта ловится одной строчкой в CI:** перегенерировать типы и упасть, если
`git diff` непустой. Значит, кто-то поменял DTO и забыл перегенерировать. Настроить можно
позже, вместе с CI в `M7-06` — сейчас достаточно, чтобы генерация была отдельным скриптом,
а не ручной командой из головы.

**Сгенерированный код исключить** из линта и форматирования, иначе он будет шуметь в каждом PR.

## На что смотрю на ревью

- Не отключён ли strict «чтобы собралось»
- Не закоммичены ли секреты (проверю историю, а не только текущее состояние)
- Скрипты запускаются из корня, а не требуют `cd apps/server`
- Настройки строгости **не продублированы** в двух конфигах
- Граница между приложениями держится правилом, а не устной договорённостью
- Правило линтера **проверено** заведомо плохим импортом, а не принято на веру
- Генерация типов — скрипт в `package.json`, а не команда из истории терминала
