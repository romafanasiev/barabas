# M1-17 — Агрегат `Hold` с поведением: `confirm()`, `expire()`

Status: needs-triage

## Задача

Hold, который **нельзя привести в невалидное состояние снаружи**. Ни одного
`hold.status = 'confirmed'` вне агрегата: есть методы, которые либо переводят состояние по
разрешённому пути, либо отказывают.

Правила, которые агрегат обязан держать сам: Hold непустой; `expiresAt > createdAt`; истёкший
Hold нельзя подтвердить; Hold принадлежит ровно одному покупателю.

## Definition of Done

- Состояние агрегата недоступно на запись снаружи
- `confirm()` на истёкшем Hold отказывает — и это тест, а не комментарий
- Время не берётся внутри агрегата из `Date.now()` напрямую — иначе «истёк» невозможно
  протестировать без ожидания; способ передачи времени выбрать и назвать
- Тесты гоняются без базы
- Агрегат ссылается на другие агрегаты по id, а не полями-объектами

## На что смотрю на ревью

- Анемичная модель — главный риск этого issue: если у `Hold` только геттеры, а правила лежат в
  сервисе, весь слой бессмыслен и это возврат
- Проверю попыткой сломать: напишу снаружи код, который приводит Hold в противоречивое
  состояние. Если получится — возврат
- Отказ должен быть выразительным: `false` без причины бесполезен на слое API в M2
- Доменные события (`SeatHeld`, `HoldConfirmed`) — здесь достаточно решить, кто их порождает;
  доставка в M5
