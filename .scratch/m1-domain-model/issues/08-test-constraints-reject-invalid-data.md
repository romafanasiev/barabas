# M1-08 — Тест: невалидные данные напрямую в БД **падают** на constraint

Status: needs-triage

## Задача

Доказать тестом, что схема защищает себя без участия приложения. Тест ходит в базу **напрямую**,
мимо сервисов, DTO и валидации, и пытается записать каждое из невозможных состояний из `06`.
Каждая попытка обязана упасть.

Это первый тест проекта, который работает с настоящим PostgreSQL. Как он поднимается — решение
этого issue (оно же готовит почву для Testcontainers в M7).

## Definition of Done

- Есть тест на **каждый** пункт списка из `06`
- Тест проверяет не только факт падения, но и **какой именно** constraint сработал: иначе
  зелёный тест может означать опечатку в другом месте
- Тест не использует ни один сервис приложения — только соединение с базой
- Тест кусается: убрал constraint из миграции → тест красный

## На что смотрю на ревью

- Проверю мутацией: сниму один `CHECK` и жду красного. Не заметил — возврат
- `expect(...).rejects` без проверки кода ошибки — слабый тест: он зелёный и когда запрос упал
  по синтаксису
- Тест должен работать на чистой базе в CI, а не только на локальной с seed-данными
