# M1 — Доменная модель и схема БД

Status: in-progress

Цель этапа: схема, которую **нельзя привести в бессмысленное состояние** — ни из кода, ни из
psql, ни случайной миграцией. И доменная модель поверх неё, в которой правила живут в
агрегатах, а не размазаны по сервисам.

Это самый длинный этап после M4 и самое слабое место по [MISSION.md](../../MISSION.md):
SELECT/JOIN пишутся, схема с нуля — нет. Оценка — 28–34 часа.

Контекст и полное описание этапа — в [ROADMAP.md](../../ROADMAP.md), раздел M1.
Единый язык — в [CONTEXT.md](../../CONTEXT.md), он же уточняется по ходу этапа.

## Definition of Done для этапа

Можешь словами защитить **каждую таблицу и каждый constraint**: зачем она, почему такие типы,
что сломается без этого ограничения. Миграции накатываются и откатываются на чистой базе.
Попытка записать невозможное состояние напрямую в базу — падает.

## Порядок работ

Номер issue — это его имя, а не очередь. Рабочий порядок такой:

1. **Решения до кода** — `01` (чем ходим в базу), `02` (ER), `13` (карта агрегатов).
   `13` обязан быть закрыт **до** `05`: как смоделирован Hold — рядами `hold_items` или
   счётчиком — определяет, возможен ли write skew в M4. См. урок `0003`.
2. **Схема** — `03`, `04`, `05`, затем `06`, `09`, `10`, `12`, и доказательства: `08`, `07`, `11`.
3. **Доменная модель** — `14`, `15`, `16`, `17`, `18`.

## Issues

- `01` ADR: выбор слоя данных
- `02` ER-диаграмма домена
- `03` Миграция: `venues`, `sections`, `seats`
- `04` Миграция: `events`, `ticket_types`, `inventory`
- `05` Миграция: `holds`, `orders`, `order_items`, `payments`, `tickets`
- `06` CHECK-constraints против невозможных состояний
- `07` Seed-скрипт: площадка, концерт, 500 мест
- `08` Тест: невалидные данные падают на constraint
- `09` Cardinality: каждая связь доказана схемой
- `10` Soft delete и partial unique index
- `11` Audit: история `orders` и `inventory`
- `12` ADR: осознанная денормализация счётчика доступности
- `13` Карта агрегатов: инвариант → агрегат → граница
- `14` ADR: транзакция на несколько агрегатов
- `15` Скелет слоёв и правило линтера на `domain/`
- `16` Value objects: `Money`, `Quantity`, `SeatLocation`, `TimeWindow`
- `17` Агрегат `Hold` с поведением
- `18` Репозиторий агрегата `Hold`: порт, реализация, мэппер
